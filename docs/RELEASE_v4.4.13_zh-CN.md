# Codex Helper v4.4.13

## 修复内容

- 同一开发目录续用 Helper 登记的原 DSH 会话，不同合同仍保留独立 ID、指纹、组键和报告。前序任务运行时本地排队，不创建额外聊天，不把他人完成事件当作本合同完成；取消排队不取消前序任务。
- 新版 DSH 原生 `session/follow` 事件订阅、可信快照水位与真实会话模型选择适配。提交、事件流、取消三项能力必须实际通过；不再以 Host 默认模型冒充当前会话模型。
- 已停止会话按可信终态区分完成、失败和用户停止；报告门禁未通过仍保持失败，不虚报成功。任务中心刷新与 Runner 使用同一租约，避免旧状态覆盖终态；提交回包也不覆盖先到达的事件与恢复记录。
- 新版 `standard` 预设的位置与 persona 前缀结构兼容；保留工具配置和后缀，仅修改合同规则。写入带备份、幂等与失败回滚。模型下拉框显示名称，不再展示内部对象字符串。
- 88FRP 优先采用运行中进程实际加载的实例配置，支持用户版和系统服务版目录；活动配置不可读或入口有歧义时保留原信任，不退回陈旧地址。运行状态无法确认时不自动重启 DSH。
- 随安装包内置目录优先、模型图片能力桥接和非安全 HTTP 浏览器兼容三项基础插件。缺失时离线安全补齐，保留已有插件、禁用状态、未知配置及认证配置；不自动启用开放访问插件。

## 验收与交付边界

- GPT 直接完成收尾代码与独立验收；没有继续让 DSH 修改 Helper 产品文件。
- 两份真实小合同使用不同组键，在同一 DSH Session 顺序完成；第二份在原上下文回忆首份暗号，未靠合同复制暗号。两份 Runner 均真实退出、报告门禁通过、产物逐一检查一致。使用 commandgoat 的 Flash 模型。
- 本机及公司电脑验证新版预设、提交、事件流、取消和真实模型目录。公司公网浏览器已看到历史目录和五个模型选项。
- 本机 WPF 截图捕获遇到图形环境错误，因此桌面像素外观未验证；模型绑定结构、真实模型目录及 Release 构建单独验证，不将其冒充视觉验收。
- 覆盖安装保留用户数据。对存在独立 DSH Windows 服务的设备，应先消除重复自启动；本次公司电脑保留旧服务配置但改为手动停止，改由 Helper 计划任务托管。

## 下载与恢复

仅发布 `codex-helper-v4.4.13-setup.exe` 和对应 SHA-256 校验文件。
安装包需要 Windows x64 的 .NET 8 Desktop Runtime，不附带 DSH、Node 或账号密钥。

基础插件、预设备份及启动入口恢复见 [新电脑基础修复说明](BASE_PLUGINS_v4.4.13_zh-CN.md)。
回退可使用先前版本安装包并按需恢复受管配置备份；已撤回的 4.4.8 功能没有恢复。
